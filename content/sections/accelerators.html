AI chip architectures

Five ways to build an AI chip

Every AI chip solves the same problem: perform trillions of multiply-accumulates per second while moving as little data as possible. Moving a number from memory costs far more energy than multiplying it. So the designs differ mainly in where they keep the model's numbers, and in how much flexibility they keep for software.

Pick an architecture to see where its memory sits and how data flows.

Number formats: how few bits can a number use?

AI models tolerate rounding surprisingly well. Halving the bits per number halves the memory each weight needs and roughly doubles the math per second. The catch is outliers: a few unusually large values stretch the scale so that ordinary values all round to the same few steps. Modern 4-bit formats fix this with block scaling: every small block of 16 or 32 numbers gets its own scale factor. Try FP4 with and without it.

Prefill and decode: two very different jobs

When you send a prompt, the chip first reads all of it in one parallel pass (prefill). That is mostly math, so it is compute-bound. Then it writes the answer one token at a time (decode), and each token needs every weight read from memory again, so it is bandwidth-bound. That is why NVIDIA pairs GPUs with the Rubin CPX for prefill and Groq-style LPUs for fast decode. Change the prompt and answer lengths and watch which phase dominates.
