Your bench: real hardware

Does your chip really work?

A simulation says what a chip should do. A test bench asks the chip itself. You set its input pins, read its output pins, and compare every answer with the simulation: a twin test. When they disagree, the pattern of wrong answers points to the broken wire, which is how engineers find defects in real chips.

The bench talks to boards through one small, open protocol, so the same test runs on the virtual board here and on a real board on your desk. Real boards are joining step by step; none is needed, and nothing on this page is locked.

Show the conversation with the board

        
How it works: the virtual board turns your design into gates (the same netlist the tiny-chip studio makes) and answers the Open Bench Protocol, one text line per command, exactly as a real board would. Input k of your design is pin ui_in[k] and output k is uo_out[k], the same order as the Verilog export, so a chip made from that export plugs straight in. The model is combinational: no clock, no timing and no analog effects, which a real chip has.

      

    


    

      
Find the faulty chip–

      

        
Four chips came off the same wafer. One has a manufacturing defect: a wire stuck at 0 or stuck at 1. Twin-test each chip, decide which one is faulty, then use the wrong answers to name the broken wire.

        

        

        

        
The defect model is the single stuck-at fault: one wire held at 0 or 1, the model test engineers have used since the late 1950s because it catches most real defects. Real defects also include wires that are slow, shorted to a neighbor or only fail when hot, which need other tests.

      

    


    

      
Build the open bench

      
Any board can join

      
The bench is open on purpose. A board joins by answering a few text commands, the Open Bench Protocol, over USB serial. That keeps the lab independent of any one company, and lets boards nobody has made yet join later.
